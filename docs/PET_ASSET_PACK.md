# 桌面宠物素材包规范与制作说明

本文档说明 LitSSH 桌面宠物的素材包格式、目录结构、动作规范、制作流程、导入导出方式以及限制条件，供素材作者、测试人员和后续开发者使用。

相关实现：

- `src/LitSSHmcp.App/Services/Pet/PetAssetService.cs`
- `src/LitSSHmcp.App/Services/Pet/PetAssetDraft.cs`
- `src/LitSSHmcp.App/Services/Pet/PetWindow.xaml.cs`
- `src/LitSSHmcp.App/Views/PetAssetEditorWindow.xaml.cs`
- `src/LitSSHmcp.App/Views/SpriteSheetImportWindow.xaml.cs`

## 1. 快速开始

推荐使用应用内编辑器：

1. 打开 LitSSH。
2. 进入“设置” → “桌面宠物”。
3. 点击“制作素材包…”或“编辑素材包…”。
4. 导入 PNG / JPG / GIF 序列帧，或使用“精灵图…”切分导入。
5. 选择动作，调整帧顺序、逐帧延迟、动作 FPS、循环设置。
6. 填写素材包名称、来源 / 作者、许可证。
7. 点击“保存并使用”。
8. 需要分发时点击“导出素材”生成 ZIP。

也可以手工制作素材目录，然后通过“导入文件夹…”或“导入 ZIP…”导入。

## 2. 素材包目录结构

素材包是一个目录，根目录必须包含 `pet.json`：

```text
pet-assets/
  <asset-id>/
    pet.json
    idle/
      0001.png
      0002.png
    walk/
      0001.png
      0002.png
    drag/
      0001.png
    click/
      0001.png
    sleep/
    stretch/
    look/
    work/
    SOURCE.txt      # 可选
    LICENSE.txt     # 可选
```

说明：

- 素材包 ID 由导入器生成，通常是 GUID；不要依赖固定 ID。
- 动作目录名固定为：`idle`、`walk`、`drag`、`click`、`sleep`、`stretch`、`look`、`work`。
- 帧路径写在 `pet.json` 中，必须是素材包根目录内的相对路径。
- 禁止使用绝对路径、`..` 路径穿越或指向素材包外部的路径。
- `SOURCE.txt`、`LICENSE.txt` 是可选的分发说明文件，导入 ZIP 时允许存在。
- 素材包 ID 为 `builtin` 的是程序内置示例，不占用磁盘目录。

## 3. pet.json 格式

### 3.1 最小可用示例

```json
{
  "name": "我的宠物",
  "version": 1,
  "fps": 10,
  "actions": {
    "idle": {
      "fps": 10,
      "loop": true,
      "frames": [
        "idle/0001.png",
        "idle/0002.png"
      ],
      "delays": [100, 100]
    }
  }
}
```

`idle` 是唯一必需动作，至少需要一帧。

### 3.2 推荐完整示例

```json
{
  "name": "示例宠物",
  "source": "https://example.com/pet-source",
  "license": "CC0-1.0",
  "version": 1,
  "fps": 10,
  "actions": {
    "idle": {
      "fps": 10,
      "loop": true,
      "frames": ["idle/0001.png", "idle/0002.png"],
      "delays": [120, 120]
    },
    "walk": {
      "fps": 10,
      "loop": true,
      "frames": ["walk/0001.png", "walk/0002.png"],
      "delays": [100, 100]
    },
    "drag": {
      "fps": 10,
      "loop": true,
      "frames": ["drag/0001.png"],
      "delays": [100]
    },
    "click": {
      "fps": 12,
      "loop": false,
      "frames": ["click/0001.png", "click/0002.png"],
      "delays": [80, 80]
    },
    "sleep": {
      "fps": 6,
      "loop": true,
      "frames": ["sleep/0001.png", "sleep/0002.png"],
      "delays": [200, 200]
    },
    "stretch": {
      "fps": 10,
      "loop": false,
      "frames": ["stretch/0001.png", "stretch/0002.png"],
      "delays": [100, 100]
    },
    "look": {
      "fps": 10,
      "loop": false,
      "frames": ["look/0001.png", "look/0002.png"],
      "delays": [100, 100]
    },
    "work": {
      "fps": 12,
      "loop": true,
      "frames": ["work/0001.png", "work/0002.png"],
      "delays": [80, 80]
    }
  }
}
```

### 3.3 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 显示名称，建议不超过 40 个字符 |
| `source` | string | 否 | 来源 / 作者 / 原始地址 |
| `license` | string | 否 | 许可证，例如 `CC0-1.0`、`MIT`、`CC-BY-4.0` |
| `version` | integer | 否 | 格式版本，当前为 `1`；高于程序支持版本会拒绝加载 |
| `fps` | integer | 否 | 默认帧率，范围 1–24，缺省 10 |
| `actions` | object | 是 | 动作集合，至少包含 `idle` |

动作对象字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `fps` | integer | 否 | 该动作帧率，1–24；缺省继承全局 `fps` |
| `loop` | boolean | 否 | 循环标记，缺省 `true`；由编辑器和后续扩展保留 |
| `frames` | string / array | 是 | 相对图片路径；字符串表示单帧，数组表示多帧 |
| `delays` | array | 否 | 每帧延迟，单位毫秒；未提供时按 `fps` 计算 |

兼容性说明：

- 动作值可以直接写成路径数组，表示没有单独参数的旧格式。
- 动作值也可以写成单个路径字符串。
- 推荐始终使用对象格式，便于指定 `fps`、`loop` 和 `delays`。
- 路径推荐使用 `/` 分隔；程序同时兼容 Windows 路径分隔符。

## 4. 动作规范

| 动作 | 用途 | 是否必需 | 缺失时行为 |
|------|------|----------|------------|
| `idle` | 待机、呼吸、眨眼 | 是 | 无法导入 |
| `walk` | 自动移动 | 否 | 使用 `idle` |
| `drag` | 用户拖动宠物 | 否 | 使用 `idle` |
| `click` | 点击宠物反馈 | 否 | 使用 `idle` |
| `sleep` | 随机睡觉 | 否 | 使用 `idle` |
| `stretch` | 随机伸懒腰 | 否 | 使用 `idle` |
| `look` | 左右看 / 等待审批提醒 | 否 | 使用 `idle` |
| `work` | AI 执行中持续工作动画 | 否 | 优先使用 `stretch`，否则使用 `idle` |

行为说明：

- `idle` 会作为大多数动作的兜底。
- `work` 缺失时优先回退到 `stretch`，这样旧素材包也能表现 AI 运行状态。
- `sleep`、`stretch`、`look` 在运行时有自己的动作持续时间，不是无限循环。
- `click` 用于点击反馈，点击后可能打开 AI 运维助手。
- `work` 在 AI 运行期间持续播放，建议做成轻量循环动画，避免大幅度位移。
- `loop` 当前由编辑器保存，运行时会按动作生命周期播放帧序列；后续可按需扩展语义。

## 5. 帧图片规范

支持格式：

- PNG
- JPG / JPEG
- GIF

推荐：

- 优先使用带透明通道的 PNG。
- 所有帧使用相同画布尺寸。
- 角色保持在相同锚点和脚底位置，否则播放时会抖动。
- 宠物窗口使用 `Uniform` 缩放，不提供逐帧锚点调整。
- 单帧建议 160×160 或 256×256，最大 1024×1024。
- 帧内容尽量贴近画布中心，避免不同动作之间跳位。
- 不要依赖超大空白边距，否则实际角色会显得很小。

GIF 说明：

- 当 `frames` 中包含 `.gif` 时，会展开 GIF 的全部帧。
- GIF 帧延迟优先使用 GIF 元数据中的延迟。
- GIF 展开后的每一帧都计入单动作帧数限制。
- 需要精确控制每帧延迟时，推荐使用 PNG 序列。

## 6. 限制与安全规则

| 项目 | 限制 |
|------|------|
| 素材包最大字节数 | 50 MB |
| 最大文件数 | 500 |
| 单动作最大帧数 | 300 |
| 单帧最大尺寸 | 1024×1024 |
| 解码像素总量 | 64M 像素，约 256 MB BGRA |
| 帧延迟最小值 | 10 ms |
| 全局 / 动作 FPS | 1–24 |
| ZIP 允许的扩展名 | `.png`、`.jpg`、`.jpeg`、`.gif`、`.txt`、`.md` |
| 禁止内容 | 可执行文件、脚本、路径穿越、素材包外路径 |

解码像素总量是压缩包大小之外的第二道限制。50 MB 的压缩素材解压后可能占用远超 50 MB 的内存，因此超过像素预算的素材包会被拒绝。

## 7. 导入方式

### 7.1 应用内编辑器

“制作素材包…”和“编辑素材包…”支持：

- 新建素材包，默认从内置 MIT 示例创建。
- 编辑已有素材包并原地保存。
- 导入多张图片。
- 导入 GIF。
- 精灵图切分。
- 动作分配。
- 拖动帧排序。
- 上下移动、删除、清空。
- 逐帧延迟。
- 动作 FPS。
- 撤销 / 重做（Ctrl+Z / Ctrl+Y）。
- 来源 / 许可证编辑。
- 未保存关闭提示。
- 复制 / 重命名。
- ZIP 导出。

### 7.2 精灵图切分

“精灵图…”导入支持：

| 参数 | 说明 |
|------|------|
| 文件 | PNG / JPG / JPEG / BMP |
| 列数 | 1–100 |
| 行数 | 1–100 |
| 帧宽 | 0 表示自动按图片宽度 / 列数计算 |
| 帧高 | 0 表示自动按图片高度 / 行数计算 |

切分顺序为从左到右、从上到下，总帧数不能超过 300，每帧不能超过 1024×1024。

### 7.3 文件夹导入

“导入文件夹…”要求：

- 目录根下有 `pet.json`，或目录只有一个子目录且该子目录内有 `pet.json`。
- 文件类型和大小符合限制。
- `idle` 动作至少有一帧。

导入后会复制到应用数据目录，并生成新的素材包 ID。

### 7.4 ZIP 导入

ZIP 支持：

```text
pet.zip
  pet.json
  idle/...
  walk/...
```

或：

```text
pet.zip
  MyPet/
    pet.json
    idle/...
```

ZIP 中不能包含可执行文件或其他未允许的扩展名。

## 8. 导出与分发

“导出素材”生成 ZIP，包含：

- `pet.json`
- 所有动作帧图片
- `SOURCE.txt`（填写来源时）
- `LICENSE.txt`（填写许可证时）

分发包建议：

1. 在编辑器中填写 `source` 和 `license`。
2. 在 `LICENSE.txt` 中写完整许可证或链接。
3. 不要放入可执行文件、脚本或来源不明的资源。
4. 使用明确的版本号，例如在文件名中写 `mypet-1.0.zip`。
5. 优先提供 PNG 序列帧，减少 GIF 兼容性问题。

内置示例：

- 内置示例由程序生成，不依赖第三方素材。
- 许可证为 MIT。
- 可以复制、编辑、导出作为模板。
- 内置素材不能直接删除或重命名，需要先复制为本地素材。

### 官方示例素材

仓库内提供可直接导入的示例素材包：

- [samples/pet-assets/README.md](../samples/pet-assets/README.md)

包含：

| 文件 | 名称 | 风格 | 许可证 |
|------|------|------|--------|
| `clay-cat-1.0.zip` | 桃桃 · 黏土粉猫 | 黏土 / 3D 矢量感 | CC0-1.0 |
| `ops-pet-1.0.zip` | 小机 · 运维桌宠 | 程序化矢量 | CC0-1.0 |
| `ops-pet-2.0.zip` | 小机 · 运维桌宠2 | 程序化矢量 | CC0-1.0 |
| `pixel-cat-1.0.zip` | 桃桃 · 像素猫 | 像素点阵 | CC0-1.0 |

这些示例均包含 8 个动作，下载后不需要解压，直接在“设置 → 桌面宠物 → 导入 ZIP…”中选择即可。

## 9. 存储维护与备份

宠物素材位于应用数据目录下的 `pet-assets`：

```text
%APPDATA%\LitSSH\pet-assets
```

如果设置了 `LITSSH_DATA_DIR`，则位于该目录下的 `pet-assets`。

在“设置” → “存储维护”：

- “存储统计”会显示“桌面宠物素材”的大小和实际路径。
- “定时备份”的新建 / 编辑计划中，可以勾选“桌面宠物素材”项目。
- 备份内容包含素材包目录、`pet.json`、动作帧以及 `SOURCE.txt` / `LICENSE.txt`。
- 恢复备份时，该目录会随其他选中项目一起恢复。

注意：内置 `builtin` 素材由程序生成，不存在于 `pet-assets` 目录；备份的是自定义素材包。

## 10. 运行与性能说明

- 宠物窗口加载完整素材包；设置页预览只加载 `idle`。
- 素材包和预览帧使用弱引用缓存，重复打开可复用。
- 设置页会显示缓存命中数、缓存条目和估算内存。
- 动画 tick 根据帧延迟动态调整，最小约 16 ms，最大约 100 ms。
- 低电量 / 远程桌面会降低动画帧率。
- 减少动态效果模式会停止自动移动和动画播放。
- 相同素材保存设置时会复用现有宠物窗口，不重新解码。
- 同一素材同时被预览和宠物窗口使用时，优先复用已加载的完整素材缓存。

## 11. 常见问题

### 导入失败：缺少 idle 动画

素材包必须包含 `idle`，并且至少有一帧。

### 导入失败：帧数超过 300

减少单动作帧数，或拆分为多个动作 / 多个素材包。

### 导入失败：单帧尺寸超过 1024×1024

缩小帧图片，保持所有帧尺寸一致。

### 导入失败：解码像素总量超过限制

减少帧数或分辨率。即使 ZIP 小于 50 MB，解码后仍可能超过内存预算。

### 导入失败：素材包版本高于当前程序支持版本

`version` 只能使用当前程序支持的版本；当前为 `1`。

### 导入失败：包含不支持的文件

ZIP 中只允许图片和 `.txt` / `.md` 说明文件。删除 `.exe`、`.bat`、`.ps1` 等文件后重新打包。

### 导入失败：路径无效

帧路径必须是素材包目录内的相对路径，不能使用 `C:\...`、`../` 或指向外部目录的路径。

### 宠物动作显示错位

检查所有帧是否使用相同画布尺寸和相同角色锚点。当前版本不支持逐帧锚点编辑。

### 自定义素材没有 work 动作

AI 运行时会自动回退到 `stretch`，如果没有 `stretch` 再回退到 `idle`。
