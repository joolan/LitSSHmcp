# 磁盘空间周期巡检 runbook（按需读取）

适用：例行巡检/周报，批量检查多台主机磁盘与 inode 水位，输出风险清单。只读为主，不做清理（清理走 disk-full 技能并经确认）。

## 1. 采集（每台主机一轮，尽量合并命令减少往返）
1. 水位：`ssh_execute_command "df -hP; df -iP"`——记录使用率 ≥80% 的挂载点（含 inode）。
2. 增长定位（仅对风险挂载点）：`ssh_execute_command "du -x -h --max-depth=1 <mount> 2>/dev/null | sort -rh | head -15"`。
3. 删除未释放句柄：`ssh_execute_command "lsof +L1 2>/dev/null | awk 'NR==1 || \$8+0>1073741824' | head"`（>1G 的占用户列重点标出）。
4. 日志体量：`log_find` 结合应用日志目录；关注单文件 >1G 且无轮转。
5. Docker 主机：`ssh_execute_command "docker system df"` 看可回收空间。

## 2. 判定阈值（巡检报告分级）
| 级别 | 条件 | 动作 |
|---|---|---|
| 正常 | 使用率 <70% 且 inode <70% | 记录即可 |
| 关注 | 70%~85%，或近 7 天日增明显 | 列出增长源，建议纳入清理计划 |
| 风险 | ≥85%，或 inode ≥85% | 报告并建议尽快处置（写失败随时可能发生） |
| 紧急 | ≥95%，或已出现 No space left | 立即升级；参照 disk-full 技能处置流程 |

## 3. 报告模板（每台主机）
- 主机 / 挂载点 / 使用率 / inode / 最大目录 Top3
- 删除未释放句柄的进程与文件
- 建议动作：清理对象（具体路径与预估释放量）、轮转配置、扩容
- 巡检时间戳，便于下轮对比

## 4. 巡检后
1. 不在巡检中执行任何删除；处置建议交用户确认后按 disk-full 流程执行。
2. 对「关注」级别记录增长速率，下轮巡检对比，提前预警。
3. 风险/紧急项写入记忆（主机、挂载点、释放量建议），下次巡检自动召回。

## 注意
- du 在大目录树上耗时长：限 `-x`（不跨挂载）并后台化可接受时再拆分。
- `/var/lib/docker` 清理用 docker 原生命令，勿直接 rm；`/proc` 等系统目录不动。
- 批量巡检串行 SSH，注意每条命令加超时，避免单台挂起拖垮整轮。
